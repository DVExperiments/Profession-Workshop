# Profession Workshop v0.4

A standalone, unofficial companion crafting planner for **World of Warcraft: Forever**, designed for GitHub Pages. Inspired by classic fantasy crafting interfaces. No login, developer API key, server or npm build required.

## Journal visual redesign (v0.4)

The app has been redesigned to match the parchment-and-leather quest journal mockup: two-page journal, embellished header, aged parchment, leather textures, brass-framed controls and parchment subpanels. The working v0.3 planner remains intact. Upload **`journal.css` and the entire `assets/` directory** alongside `index.html` or the journal styling will not render correctly. Assets are part of this package and do not rely on third-party image servers.

## What works

- Search/filter an imported profession catalog; client-derived recipes are attributed to [AHledger](https://ahledger.com).
- Set a target quantity and recursively resolve ingredient requirements.
- Apply locally tracked inventory to the whole dependency tree (including pre-crafted intermediates).
- Show materials, a branching tree, a shopping checklist, and source notes.
- Save multiple objectives; create custom recipes; back up and restore your personal data.
- Browser-side best-effort refresh of AHledger's **public keyless** crafting endpoints, caching only complete imports locally.
- Static snapshot generated by a daily GitHub Action with no API key.

## Important data setup

This ZIP intentionally includes an **empty** `data/recipes.json`. The developer environment could verify AHledger's documented API but could **not fetch the JSON body**, so a full catalog has **not** been presented as downloaded or verified. Run the import workflow in your repository to populate the real client-extracted recipes. No invented recipes are included.

1. Upload **all contents of this folder**, including `.github/workflows/update-recipes.yml`, `scripts/update_recipes.py`, `data/recipes.json`, and `index.html` to your repository root. If you upload via GitHub's web UI, make sure hidden `.github` contents are included.
2. In **Settings → Pages**, select *Deploy from a branch*, branch `main`, folder `/ (root)`.
3. In **Actions → Update Forever recipe snapshot**, select **Run workflow**.
4. The workflow fetches the documented `GET /v1/crafting/{market}?profession=...&all=1` endpoint across professions, normalizes reagent relationships, and commits a new `data/recipes.json`. GitHub Pages then serves that static catalog. It repeats daily by schedule.
5. If GitHub Actions cannot push, enable **Settings → Actions → General → Workflow permissions → Read and write permissions** or use a separate PR workflow.

### Data limitations

- The import uses AHledger's public, documented **crafting** endpoint, not a bulk-database dump. It may not provide all professions, locations, or noncrafting abilities. Recipes are marked as sourced from AHledger rather than independently confirmed in the live game.
- Currently the importer is intentionally **fail-closed**: a network or format error, or fewer than 100 records, causes the Action to fail instead of overwriting previous recipe data with a partial export. The site will still work for custom recipes.
- A website cannot automatically see your in-game bags. Inventory is entered manually for now.
- Some crafting outputs have variable yields: we use the minimum reported yield for conservative calculations.
- Recipe acquisition values such as `trainer` are not sufficient to identify a trainer's exact NPC/location. Source notes can be entered manually; never assume a specific drop location.
- When multiple recipes produce the same item, v0.4 selects the first matching imported recipe for intermediate crafts. Choosing an alternate method is planned for v0.4.
- The browser's direct refresh needs AHledger to permit cross-origin browser requests (CORS); the GitHub Actions route does not depend on CORS.
- The website uses original CSS decoration and emoji placeholders, not copyrighted Blizzard interface textures.
